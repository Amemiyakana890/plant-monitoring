# 要件定義書

## 1. システム概要

植物の育成環境をATOM Matrixで取得し、スマートフォンアプリ「植物見守り」から確認できるIoTシステム。

## 2. システムの目的

- 植物の状態を見える化する
- 育成をサポートする
- センサーデータを記録する
- 植物の管理を分かりやすくする
- 普段は意識せず、必要な時だけ状態を知らせる

## 3. 利用者・利用シーン

### 利用者

| 利用者 | 内容 |
|---|---|
| 植物を育てる人 | 日常的な管理 |
| 初心者 | 育成サポート |

### 利用シーン

- 朝、植物の状態を確認する
- 外出先から状態を確認する
- 水やりの判断材料にする
- 過去の環境変化を確認する
- 通知が来た時だけアプリを開いて詳細を確認する

## 4. 機能要件

画面構成(ホーム / 植物詳細 / 履歴 / 通知・アラート / 設定・植物登録)に対応する形で機能を定義する。

| No | 画面 | 機能 | 説明 |
|---|---|---|---|
| F-01 | ホーム | 植物の状態表示 | 登録した植物の状態(アイコン+メッセージ)をカードで表示 |
| F-02 | ホーム | 環境データ表示 | 現在の温度・湿度・土壌水分・照度をまとめて表示(照度はBH1750で実接続済み。9章を参照) |
| F-03 | 植物情報 | 植物情報の確認・編集 | 植物名・植物種など基本情報を確認・編集(植物種はカタログから選択。モンステラ・パキラ・サンセベリア・ポトスの4種に対応) |
| F-04 | 履歴 | 履歴グラフ表示 | 過去の環境データをグラフで確認 |
| F-05 | 通知/アラート | 状態悪化通知 | 状態が悪化した際に通知 |
| F-06 | 通知/アラート | 通知一覧表示 | 過去の通知履歴を確認 |
| F-07 | 設定/デバイス登録 | デバイス接続 | ESP32デバイスとのペアリング |
| F-08 | 設定/デバイス登録 | 植物登録(初回) | 植物名・植物種の初回登録、デバイスとの紐付け(アプリ内の登録画面から`POST /plants`まで実装済み) |
| F-09 | 設定/デバイス登録 | 通知設定 | 通知頻度・通知時間帯・通知音の設定 |
| F-10 | 共通 | ESP32通信 | センサーデータをデバイスから取得 |

## 5. 非機能要件

| 項目 | 内容 |
|---|---|
| 応答時間 | 数秒以内に画面へ反映 |
| 通信 | ローカルネットワーク(Wi-Fi) |
| データ保存 | SQLite |
| 対応OS | iOS / Android |
| UI | 初心者でも操作しやすい、情報量を抑えた画面構成 |
| デザイン | デザインシステムに準拠した一貫性のある見た目 |

## 6. デバイス要件(ハードウェア)

| 項目 | 内容 |
|---|---|
| マイコン | ATOM Matrix(Wi-Fi/Bluetooth対応) |
| センサー | ENV Ⅲ(温度・湿度・気圧)、土壌水分センサー(外付け、実接続済み)、照度センサー(BH1750、実接続済み。9章を参照) |
| 電源 | 小型モバイルバッテリー |
| 充電管理 | USB-C充電 |
| 通知手段 | フルカラーステータスLED(緑:正常 / 橙:注意 / 赤:エラー) |
| 操作 | リセットスイッチ(Wi-Fi設定リセット用) |
| 動作温度 | 0〜50℃ |
| サイズ | 約35mm × 18mm × 98mm(突起部含まず) |
| 重量 | 約30g |
| 外装 | マットな質感、防滴設計、屋内利用を想定 |

## 7. デザイン要件

- デザインシステム(カラー・タイポグラフィ・コンポーネント)に準拠する
- 基本カラーは Deep Green を基調とし、状態は Success(緑) / Warning(橙) / Error(赤) の3色で表現する
- フォントは Noto Sans JP を使用する
- ボトムナビゲーションは「ホーム / 植物 / 履歴 / 通知 / 設定」の5項目で統一する

詳細は[設計書 7章](system-design.md#7-デザインシステム)を参照。

## 9. 制約事項

- ローカルネットワークのみで動作する
- 自動給水は実装しない
- センサーは温度・湿度・土壌水分・照度に対応する。土壌水分センサーは実接続済み
- **照度センサーはBH1750を採用し実接続済み**(ENV IIIとは別のI2Cバス(Wire1、SDA=GPIO26/SCL=GPIO32)を使用)。当初はM5Stack用光センサユニット(U021、GPIO接続)を採用予定だったが、購入しようとした時点で品切れとなっており入手できなかった。もともと拡張ベース経由でのI2C/ADCピン競合・ピン不足の懸念も抱えていたため、それらも踏まえてBH1750へ変更した。追加にあたり土壌水分センサー(U019)の配線をATOM PortABC拡張ベースのPort B経由(GPIO33)に戻している(GPIO32をBH1750のI2Cバスに使うため)。Port B経由は過去に異常値が出た経緯がある配線のため、キャリブレーションモードでの再検証が必須(詳細は`esp32/plant_sensor_integrated/plant_sensor_integrated.ino`内のコメントを参照)。**2026-08-21時点で約2週間の実運用を確認し、異常値の再発は見られていない**が、GPIO33構成での正式なキャリブレーション(SOIL_RAW_DRY/WETの再実測)自体はまだ実施できておらず、引き続き今後の課題としている(詳細は[デバイス検証ログ01](device-test-log01.md)を参照)
- iOS / Androidの両方を対象とする
- デバイスは1台につき植物1株を想定する
- **v1企画時点では認証機能を実装しない(単一ユーザー・単一端末での利用を前提とする)方針だったが、v2でFirebase Authentication(メール/パスワード)によるログイン機能・サーバーAPIの保護を追加した**(詳細は[v2-firebase-security-design.md](v2-firebase-security-design.md)を参照)。ただし現時点では「本人確認のゲート」としての導入にとどまり、ユーザーごとにデータを分離する仕組みではないため、複数端末間でのデータ共有(同じアカウントでログインすれば同じ1件のデータが見える)という単一ユーザー構成の実態は変わっていない
- **本バージョン(v1)ではアプリが管理する植物・デバイスは1つのみとし、複数登録には対応しない**。画面構成もこれに合わせた単独表示とし、複数植物・複数デバイスへの対応は将来のバージョンで検討する([企画書 11章](concept.md#11-今後の展望)を参照)
