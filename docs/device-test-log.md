# デバイス検証ログ

このドキュメントは、センサーデバイス(ATOM Matrix周り)のハードウェア検証・トラブルシューティングの記録です。

`concept.md` / `requirements.md` / `system-design.md`は「最終的にこう決まっている」という仕様書のため、検証中の試行錯誤(症状→切り分け→結論)はこちらに時系列で記録し、仕様書側は常に「現時点の決定事項」だけを反映するようにする。

## 2026-07-25: 土壌水分センサー(M5Stack Unit Earth / U019)接続テスト

### 使用機材

- ATOM Matrix + ATOMIC PortABC拡張ベース
- M5Stack用 土壌水分センサユニット(Unit Earth, U019、抵抗式)
- 接続: 拡張ベース Port B(HY2.0-4P、同梱のGroveケーブル使用)
- 読み取りピン: GPIO33(Port Bのアナログ出力。過去の検証で実績あり)

### 経緯・症状(時系列)

1. **初回テスト**: `raw = 0`で固定。当初は「プランターに挿していないから」と推測。後にセンサー仕様(乾燥時=低い値、湿潤時=高い値の抵抗式)と方向性が一致することが分かり、この時点では正常動作の可能性ありと判断していた。
2. Port Bの信号線がGPIO23/33のどちらか特定するため、両方を読む診断コードに変更 → **どちらも0のまま変化なし**。
3. Groveケーブルを挿し直したところ、GPIO33が水分(水に浸けるテスト)に反応するようになった。**1回目の接触不良を特定・解消**。
4. 実際の土に挿してキャリブレーションを試みたところ、**再び値が不安定に**(空気中: 411〜589 / 土中のはずが: 295〜1907など、方向性も矛盾)。
5. 1回の読み取り(10サンプル)内でのブレ(min/max)を可視化する診断を追加 → **数十ms単位でmin/maxが大きく開く**ことを確認(例: min=32, max=2042)。土壌水分がミリ秒単位で変わることはあり得ないため、電気的な接触不良と判断。
6. さらにセンサーを固定した状態でテストしたところ、**読み取りごとに完全に0になったり戻ったりする**挙動を確認(接続が物理的に切れる瞬間があることを示唆)。
7. 最終テストでは、逆に`raw = 4095`(ADC最大値)に張り付く現象が発生。Unit EarthのVCCは5V系のため、信号線に5V系の電圧がそのままかかっている(過電圧)可能性を懸念し、**安全のため取り外して検証終了**。

### 実施した切り分けテスト

| テスト | 結果 | 分かったこと |
|---|---|---|
| 内蔵プルアップ(`INPUT_PULLUP`)有効化 | 0のまま変化なし | 信号線は「浮いている(未接続)」のではなく、何かに能動的に引っ張られている |
| GPIO23 / GPIO33 両方読み取り | どちらも同じ傾向(0固定) | ピンの選択ミスではない |
| Groveケーブルの挿し直し | 一時的に改善 | 接触不良が濃厚(1回目) |
| min/max(サンプル内ブレ)確認 | 数十ms単位で大きく変動(例: 32〜2042) | 環境変化では説明できない、物理的な接触不良 |
| センサー固定した状態での再テスト | それでも0⇔有意値を繰り返す | 「触れると動く」レベルの緩みではなく、より深刻な接触不良 |

### 結論

- Unit Earth(U019)・接続ケーブル・拡張ベースのコネクタのいずれかに**物理的な不良がある**可能性が高い(切り分けの範囲では個体特定までは至らず)。
- 加えて、M5Stack公式ドキュメント上もこのセンサーは「電極が防錆・防水加工されていないPOC(検証)用途限定」であり、そもそもプランターに挿しっぱなしにする本プロジェクトの用途(継続的な「見守り」)とは相性が良くないことが判明した。
- 上記2点(信頼性の問題 / 用途との不一致)から、**ADOFUN 土壌水分センサー検出モジュール 土壌水分試験 土壌水分試験対抗への変更を決定**。

### 今後の対応

- SEN0308到着後、`esp32/soil_moisture_capacitive_test.ino`でキャリブレーション(`SOIL_RAW_DRY` / `SOIL_RAW_WET`の実測)を行う。
- Unit Earth自体の故障原因(ケーブル起因か、センサー個体起因か、拡張ベース側のコネクタ起因か)は完全には特定できていない。予備のGroveケーブルがあれば追試の余地はあるが、優先度は下げる。
- センサー変更に伴い、`README.md`の使用技術表と`system-design.md`8章(デバイス設計・部品構成)の更新が必要(別途対応)。

### 関連ファイル

- `esp32/soil_moisture_test.ino` — Unit Earth用の診断・キャリブレーションスケッチ(min/max表示付き)、ENV Ⅲ + 土壌水分センサーの統合スケッチ(センサー種別切り替え対応)

## 2026-07-31: ESP32実機からのWi-Fi自動送信・モバイルバッテリー給電テスト

### 使用機材

- ATOM Matrix + ATOMIC PortABC拡張ベース
- M5Stack用温湿度気圧センサユニット Ver.3(ENV III、Port A・I2C接続)
- 小型モバイルバッテリー(USB-C給電)

### 経緯・結果

1. `esp32/plant_sensor_integrated.ino`にWi-Fi接続 + `POST /sensor`送信処理を実装。
   Wi-Fi情報・サーバーIPは`.env`と同じ考え方で`secrets.h`(Git管理対象外)に分離し、
   `secrets.h.example`をテンプレートとしてコミットする形にした。
2. サーバー側は同一LAN内の別デバイスからのアクセスになるため、Windows Defender
   ファイアウォールで3000番ポートの受信を許可する対応が必要だった
   (`New-NetFirewallRule`、または`node app.js`初回起動時のポップアップから許可)。
3. 上記対応後、ATOM MatrixからNode.jsサーバーへの自動送信(30秒間隔)が成功。
   シリアルモニタで`HTTP 201`とstatus判定結果を継続的に確認できた。
4. Flutterアプリ側に自動ポーリング(30秒間隔でplant/notificationsを再取得)を追加し、
   アプリを操作せずに置いたままでも、ESP32からの最新値が自動で画面に反映されることを確認。
5. 給電を USB電源から小型モバイルバッテリーに切り替えて動作確認。問題なく動作した
   (要件定義書6章の電源要件を実機で確認できた)。

### 結論

- ENV III分については「センサー → ESP32 → Node.js → SQLite → Flutter」の一気通貫が
  実機・モバイルバッテリー駆動の状態で確認できた。
- 土壌水分(`soil`)は`SOIL_SENSOR_CONNECTED = false`により固定値50を送信している仮の状態。
  照度も未配線のため常に0が送信されている。どちらもセンサー到着後に対応する。

### 今後の対応

- 土壌水分センサー(SEN0308)・照度センサー到着後、`plant_sensor_integrated.ino`の
  `SOIL_SENSOR_CONNECTED`を`true`にし、`readSoilMoisture()`を実測に差し替える。
  照度センサーも配線後、同様にプレースホルダー送信を実測に置き換える。

## 2026-08-02: 土壌水分センサー(DFRobot SEN0308・静電容量式)接続・キャリブレーションテスト

### 使用機材

- ATOM Matrix + ATOMIC PortABC拡張ベース
- DFRobot Gravity 防水静電容量式土壌水分センサー V2.0(SEN0308)
- 接続: 拡張ベース Port B(HY2.0-4P、Groveケーブル)、読み取りピンはU019検証時と同じGPIO33を踏襲
- 検証スケッチ: `esp32/soil_moisture_capacitive_test.ino`(新規作成。安定性チェック/キャリブレーション/通常動作確認の3モードを切り替え可能)

### 経緯・結果(時系列)

1. **接続直後の安定性チェック**: `MODE_STABILITY_CHECK`で計測したところ、`avg=671, diff=3〜11`程度で終始安定。U019のときのような数十ms単位の暴れ(diff数百〜数千)は一切見られず、**接続自体は良好**と判断。
2. **キャリブレーション(空気中/水中)**:
   - 空気中(完全に乾いた状態): `RAW avg=702`
   - 水に浸けた状態: `RAW avg=751`
   - センサー本体のDRY/MOIST/WET表記の挙動(水につけるとWET側、取り出すとDRY側)とも整合。`WET(751) > DRY(702)`という関係を確認。
   - `map()`は数値の大小に関係なく線形補間するため、コード側の変換ロジック(`map(raw, SOIL_RAW_DRY, SOIL_RAW_WET, 0, 100)`)はそのままで問題なし。
3. **`MODE_NORMAL`切り替え直後に`soil=0%`固定という事象**が発生。RAW値を確認すると`avg=623`と、キャリブレーション時のDRY(702)を大きく下回っていた。
   - 電源・USB接続・配線はいずれも変更していないことを確認(ハードウェア要因の切り分け)。
   - `MODE_STABILITY_CHECK`で経過観察したところ、`656→682→702付近`と**時間経過とともに徐々に上昇し、当初のDRY値(702)に収束**していく挙動を確認。
   - センサー表面を拭いた直後は650〜700付近まで回復しており、**水没テストの残留水分が乾くまでのドリフト**が原因と判明(ハードウェア不良ではない)。
4. **実際の土での計測**:
   - 乾いた土(未潅水): `RAW avg=713`(diff 7〜10で安定)
   - 水やり直後: `RAW avg=704`と、乾いた土より一時的に低い値が出た(想定と逆の順序)。
   - 数分放置して再計測したところ`avg=720`まで上昇。**水が土中のセンサー位置まで浸透するのに数分のタイムラグがある**ことが原因と判明。
5. **さらに数分後、`avg=727`まで上昇した直後に`avg=667`まで急落し、その後`avg=725`まで回復する事象**を観測(diffは最大11)。U019のときのような深刻な接触不良(0⇔4095に張り付く、数十ms単位で暴れる)とは異なるが、**原因未特定の一過性の落ち込み**であり、注意深く監視が必要な事象として記録する。

### 実施した確認事項まとめ

| 確認項目 | 結果 | 分かったこと |
|---|---|---|
| 接続直後の安定性(min/max) | diff最大11程度で安定 | U019のような接触不良は見られない |
| 空気中/水中のキャリブレーション | DRY=702 / WET=751(差49) | 方向性はセンサー表記と一致。ただし差が小さくノイズの影響を受けやすい |
| キャリブレーション直後の`soil=0%`固定 | RAW=623まで低下 | 電源・配線は無変更。水没試験の残留水分によるドリフトと判明(数分で702付近に回復) |
| 乾いた土 vs 水やり後の土 | 乾いた土=713 / 水やり直後=704 / 数分後=720 | 水やり直後は一時的に値が下がる(浸透のタイムラグ)。数分待てば順序は正常化する |
| 長時間観察中の急落 | 727→667→725 | 原因未特定。一過性の変動だが、U019ほど深刻ではない |

### 結論

- SEN0308は**接続自体は安定**しており、U019のような物理的な接触不良は見られない。
- ただし以下の2点は、実装・運用上の考慮が必要:
  1. **残留水分によるドリフト**: センサーが濡れた状態から乾く際、RAW値が数分かけて緩やかに変化する。水やり直後のセンサー値は数分間「過渡的な値」である可能性があるため、状態判定(healthy/thirsty/dry)にすぐ反映させると誤判定を招く恐れがある。
  2. **土の中でのDRY-WET差が小さい**(乾いた土713 → 湿った土720で差はわずか7)。空気中/水中の校正(差49)よりもさらに狭く、ノイズ(diff 3〜11)の影響を受けやすい。現状の空気中/水中ベースのキャリブレーション値(DRY=702, WET=751)を暫定的に使う分には大きく外れていないが、**将来的には実際の土での複数点キャリブレーションに切り替えることを検討したほうがよい**。
- 727→667→725の急落は、原因が完全には特定できていない(センサー個体の問題か、外的要因かは不明)。今後同様の事象が再現するか継続的に注視する。

### 今後の対応

- `plant_sensor_integrated.ino`へ実装反映する際は、下記を検討する:
  - `SOIL_SENSOR_CONNECTED = true`にし、`readSoilMoisture()`を今回のキャリブレーション値(DRY=702, WET=751)を用いた変換ロジックに置き換える
  - 水やり直後の数分間は値が過渡的になりうるため、複数サンプルの移動平均や、急激な変化を一定時間ならしてから通知判定に使うなどの緩和策を検討する
  - 土でのDRY-WET差が小さいため、必要に応じて土そのものでの複数点キャリブレーションへの切り替えを検討する(現状は空気中/水中の値を暫定採用)
- 727→667→725の急落について、再現性があるか今後の実機テストで継続観察する
- 照度センサー(U021)の配線・実接続テストに着手する
