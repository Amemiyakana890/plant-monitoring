# 企画書

## 1. プロジェクト概要

「植物見守り」は、植物の育成環境を専用センサーデバイスで取得し、スマートフォンアプリから状態を確認できるIoTシステムです。
「植物のことを、ずっと気に掛けなくてもいい。必要な時だけ、そっと知らせる」をコンセプトに、植物の状態を「見える化」することで育成をサポートします。

## 2. 制作背景

植物は温度・湿度・水分量・日当たりなどの環境によって生育状態が変化します。しかし初心者は植物の状態を判断することが難しく、水やりのタイミングや環境の変化に気付きにくいという課題があります。
そこで、環境データをリアルタイムに確認でき、かつ「毎日見なくても安心できる」システムを制作し、植物の管理を支援したいと考えました。

## 3. 課題

- 植物の状態が見た目だけでは分かりにくい
- 水やりの判断が難しい
- 過去の環境変化が分からない
- 初心者は育成に失敗しやすい
- 常にアプリを確認する必要があると続かない

## 4. コンセプト・デザインの方向性

**コンセプト:「静かに見守る」**

- 何も通知が来ていない = 安心、という状態を基本とする
- 数値の羅列よりも、状態(アイコン+短いメッセージ)を優先して表示
- 必要なときだけ詳細を見られる導線にする
- 自然を感じるやさしい色合いと十分な余白で、「安心感」と「見やすさ」を両立するデザインシステムを採用
- 本バージョンでは1台のデバイス・1株の植物を管理する単独構成とし、画面もそれに合わせたシンプルな作りとする(詳細は[要件定義書 9章](requirements.md#9-制約事項)を参照)

デザインシステムの詳細(カラー・タイポグラフィ・コンポーネント)は[設計書 7章](system-design.md#7-デザインシステム)を参照してください。

## 5. 解決方法

温度・湿度・土壌水分・照度をESP32ベースのセンサーデバイスで取得し、Flutterアプリへ送信します。アプリでは現在の状態だけでなく履歴も確認でき、植物の変化を把握しやすくします。また、状態が悪化した場合のみ通知することで、普段は意識せずに済む「見守り」体験を実現します。

## 7. 想定利用者

- 家庭菜園を始めた人
- 観葉植物を育てている人
- 学校で植物を管理する人
- 植物を育てたいが、日々の確認や管理に自信がない初心者

## 8. 主な機能(画面別)

| 画面 | 機能 | 説明 |
|---|---|---|
| ホーム | 植物の状態表示 | 登録した植物の状態(アイコン+メッセージ)とセンサー値をカード形式で表示 |
| 植物情報 | 植物情報の確認・編集 | 登録した植物の名前・植物種などの基本情報を確認・編集 |
| 履歴 | 環境データ推移表示 | 過去のセンサーデータをグラフで確認 |
| 通知/アラート | 状態悪化通知 | 水やりや環境改善が必要な際に通知 |
| 設定/デバイス登録 | デバイス接続・各種設定 | デバイスのペアリングや通知設定など |

## 9. プロダクト(センサーデバイス)概要

植木鉢に挿して使う、目立たないデザインの専用デバイスを開発します。

- ATOM Matrixを中心に、ENV Ⅲ(温湿度・気圧)センサー、土壌水分センサー、照度センサーを搭載
- モバイルバッテリーでの駆動に対応
- ステータスLEDにより通信・エラー状態を色で表示
- ミルクホワイト / セージグリーン / グレージュの3色展開を想定

詳細な部品構成・仕様は[設計書 6章](system-design.md#6-デバイス設計)を参照してください。

## 11. 今後の展望

- 通知機能の強化(通知タイミングのカスタマイズ等)
- セキュリティ関連の強化(v2でFirebase Authenticationによるログイン・サーバーAPIの保護までは実装済み。詳細は[v2-firebase-security-design.md](v2-firebase-security-design.md)を参照)
- 複数植物・複数デバイスへの対応(現状は1台1株の単独構成。例えばモンステラとパキラを同時に2株登録して見守る、といった使い方はまだできない。なお「1株について4種の中からどの植物種を育てているか選ぶ」機能〈植物種選択・切り替え〉自体はモンステラ・パキラ・サンセベリア・ポトスの4種で実装済み。両者は別の課題であり、複数株を並行管理する機能は未着手)
- 履歴グラフ機能の改善(期間指定、比較表示など)
- クラウド対応によるリモートアクセス
- Firebaseの活用範囲拡大(Authentication・Cloud Messagingの導入は完了。サーバー自体をNode.jsからCloud Functions等へ置き換える案は検討したが、既存の判定ロジックとの相性を踏まえNode.jsサーバーを`firebase-admin`で拡張する方針に決定した。詳細は[push-notification-design.md 9-1章](push-notification-design.md)を参照)
